# dnd-ai

A local-only client for playing D&D 5e (SRD 2024 rules) solo with an AI as Dungeon Master. An
MCP server owns campaign state, character sheets and every die roll so the AI never has to
invent a number or remember a rule under pressure. A companion browser window shows the
character sheet, dice log and glossary live while you chat.

## Requirements

- Node 24, PowerShell 7 (Windows 11)
- ChatGPT Plus with Developer mode enabled (chatgpt.com -> Settings -> Apps -> Advanced), and
  the OpenAI Secure MCP Tunnel client already installed at
  `%USERPROFILE%\tools\tunnel-client\tunnel-client.exe`
- or Claude Desktop, as a local stdio fallback (see `docs/claude-desktop.md`)

## Quick start

```powershell
.\start.ps1
```

This installs dependencies and builds the server and companion UI if needed, starts the server
in the background, starts the OpenAI tunnel, and opens the companion window in your browser. It
prints a status block with the server URL, tunnel status and log paths, including separate
stdout/stderr logs for the tunnel (`tunnel.log` / `tunnel.err.log`). Run `.\start.ps1
-NoTunnel` to skip the tunnel (Claude Desktop only) or `-NoBrowser` to skip opening the browser.
It refuses to start a second time while a server is already running - run `.\stop.ps1` first.

```powershell
.\stop.ps1
```

Stops the server and the tunnel client and confirms port 8765 is free.

## Playing

Open a chat at chatgpt.com, add the `dnd tunnel` app to the chat, and either type `/resume` to
pick up a saved story or ask to start a new one. Keep the companion window open on a second
monitor - it updates live as the AI calls tools. To jump the companion straight to a specific
story, open `http://127.0.0.1:8765/?campaign=<id>`.

## Portraits

Portraits draw themselves and appear in the companion window: one for every new character, and
for a fight one portrait per creature type - shared by all of them, dealt round-robin when a type
has several - plus one of their own for anyone with a name, a `unique: true` enemy or a named
humanoid. The DM calls `generate_portrait` only to add a variant for a type (up to 4) or to
redraw one fighter from a description. Set `auto_portraits: false` in the campaign settings to
turn the automatic ones off. Images are generated by Cloudflare Workers AI (FLUX.1 schnell) and
stored under `data/portraits/`, served at `/portraits/`.

It is off until two environment variables are set in the PowerShell window you run `.\start.ps1`
from (`.\start.ps1` prints `Portraits: enabled` or `disabled` in its status block):

```powershell
$env:CLOUDFLARE_ACCOUNT_ID = '...'   # dash.cloudflare.com -> your account -> Account ID
$env:CLOUDFLARE_API_TOKEN  = '...'   # My Profile -> API Tokens -> Create Token -> Custom token
                                     # with permission Account -> Workers AI -> Read
```

The Workers AI free tier is 10,000 neurons a day, about 170 portraits at 1024x1024, and only the
prompt text leaves the machine. Without the variables the tool says it is unavailable and the
player can drop their own image onto a character in the companion window instead - which also
works when the variables are set.

## Architecture

- The MCP server (`src/`) owns all game state (SQLite, `better-sqlite3`) and dice
  (`@dice-roller/rpg-dice-roller`); the AI only narrates.
- Database file: `data/dnd-ai.sqlite`, schema in `src/db/migrations/` (up to `018_combat_flags.sql`).
- Two transports: streamable HTTP at an unguessable secret path (`src/transport/http.ts`), for
  the OpenAI tunnel, and stdio (`src/bin/stdio.ts`), for Claude Desktop.
- The companion window (`web/`) is a Svelte 5 app built with Vite and served as static files by
  the same Express process, plus a `/ws` feed for live updates.
- The OpenAI Secure MCP Tunnel is outbound-only from this machine - there is no public URL or
  open inbound port.

## Tools (87)

- **Campaign**: `list_campaigns`, `create_campaign`, `load_campaign`, `mark_story_filled`
- **Record**: `save_checkpoint`, `end_session`, `update_objectives`, `log_event`,
  `add_canon_fact`, `add_glossary_entry`
- **Story**: `set_story_outline`, `add_act`, `open_chapter`, `advance_chapter`,
  `add_plot_thread`, `update_plot_thread`, `plant_clue`, `find_clue`, `add_rumour`,
  `get_rumours`, `advance_time`, `set_calendar`, `roll_table`, `read_journal` - acts and
  chapters, threads and clues, the in-game calendar with season and weather, seeded random
  tables and the player's own journal
- **Codex**: `upsert_entity`, `link_entities`, `get_codex`, `get_entity`, `set_voice_card`,
  `entity_tree` - NPCs, factions, places and items with relationships and voice cards
- **Progression**: `note_play`, `get_play_profile`, `propose_feature`,
  `propose_level_up_options`, `create_background`, `propose_subclass`, `propose_spell`,
  `save_to_library`, `list_library` - homebrew subclasses and spells priced against the SRD,
  custom backgrounds and level-up suggestions from how the player plays
- **Guide**: `read_guide` - the long DM procedure for `story`, `codex`, `progression`, `combat`
  and `rolls`, kept out of the project text
- **Dice**: `roll` - with `roller: "player"` the player clicks the die in the companion window
- **Character**: `get_character_sheet`, `list_character_options`, `srd_lookup`,
  `create_character`, `apply_damage`, `heal`, `set_temp_hp`, `set_condition`, `death_save`,
  `stabilize`, `set_exhaustion`, `rest`, `prepare_spells`, `learn_spell`, `add_language`,
  `grant_language`, `use_spell_slot`, `award_xp`, `grant_level`, `level_up`, `grant_feature`,
  `grant_inspiration`, `spend_inspiration`
- **Inventory**: `adjust_gold`, `add_item`, `remove_item`, `equip_item`, `list_inventory` -
  gold, stacks, equipping armour (AC is recomputed) and carrying capacity (STR x 15 lb; over it
  the effective speed drops to 5 ft unless the `encumbrance` setting is `off`)
- **Party**: `create_companion`, `list_party`, `retire_companion`, `promote_companion`
- **Combat**: `start_encounter`, `add_combatant`, `get_battle_state`, `find_position`,
  `move_token`, `attack`, `use_action`, `apply_effect`, `end_effect`, `set_combat_condition`,
  `advance_turn`, `undo_last_combat_action`, `end_encounter`
- **Portraits**: `generate_portrait`

## Campaign settings

Set in the companion window or with `create_campaign`: `rules_mode` (`strict`, `flexible`,
`freeform` - how hard the server holds the DM to the rules when it invents something),
`xp_mode` (`xp` or `milestone`), `auto_portraits` and `encumbrance` (`rules` or `off`).

The player's own dials - `visibility`, `cheat_mode`, `luck_bias`, `roll_mode`, `player_rolls`
(`all`, `d20_only`, `none`), `roll_timeout_s` and `show_secrets` (the spoiler toggle) - are set in
the companion window only; the DM never sees them and `create_campaign` drops them if passed.

## Rules coverage

The engine enforces the 2024 SRD 5.2.1 rules rather than leaving them to the DM's prose:
conditions and their mechanical effects, action economy (one action/bonus action/reaction a
turn, Extra Attack and Multiattack), grapple and shove as opposed unarmed strikes, spell slots
and spell entries read straight from the SRD (attack rolls, saves, damage, upcasting),
proficiencies in skills, tools and languages, exhaustion, going stable at 0 HP, prepared-caster
spell lists, and feats with their own numbers. See `docs/guide/combat.md` for improvised
actions and logged rulings, `docs/guide/progression.md` for the prepared/known spell model, and
`docs/guide/rolls.md` for tool and language checks.

## Backups

The server writes a consistent `VACUUM INTO` snapshot of the campaign database to
`data/backups/` about 5 seconds after startup and every 24 hours after that (skipped if one from
the last 20 hours already exists), keeping the newest 14 files. The directory is configurable via
`DND_BACKUP_DIR`. Run `npm run backup` to take one by hand (build first with `npm run build`).

## Troubleshooting

- **Port 8765 already in use**: run `.\stop.ps1`, then `.\start.ps1` again.
- **Tunnel calls return 404 on initialize**: a stale server is still holding port 8765 under a
  different secret - `.\stop.ps1` then `.\start.ps1`.
- **`CONTROL_PLANE_API_KEY` missing**: `.\start.ps1` needs it in the current window to start the
  tunnel; create a runtime API key with Tunnels Read + Use at
  https://platform.openai.com/settings/organization/api-keys and `$env:CONTROL_PLANE_API_KEY =
  '...'` before running `.\start.ps1`, or pass `-NoTunnel` to skip it.
- **Companion shows "companion UI not built" in the server log**: run `npm run build:web` (or
  `.\start.ps1`, which builds it automatically when stale).
